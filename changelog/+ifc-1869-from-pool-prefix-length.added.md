When allocating an IP address from a pool (the `from_pool` directive on an IP address pool), you can now request a specific prefix length instead of always using the pool's default. In the UI, selecting an IP address pool shows an optional prefix-length field next to the value input, with the pool default as a placeholder — leave it empty for the default, or enter a value to override it.

Allocation remains idempotent: once an address is reserved for an object's relationship, its `(address, prefix length)` cannot be changed by re-allocating. Re-selecting the pool without entering a prefix length reuses the existing reservation. Requesting a prefix length that conflicts with an existing reservation now returns a clear error (`its prefix length cannot be changed, only /<n> can be used`) rather than silently ignoring the request.
