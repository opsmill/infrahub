Added the GraphQL API for repository git visibility. `InfrahubRepositoryCommits` answers for the branch you are viewing with the remote branch or tracked ref it follows, the commit Infrahub has imported, and a paged commit log read live from a worker's local copy, each commit labelled as imported, pending, history, unrelated or at the remote head. It reports when the remote history was rewritten, when the imported commit no longer exists in the local copy, and when a read-only repository's tracked branch or tag has been deleted upstream as of the worker's last fetch, in which case it still lists the history Infrahub is running. A worker that has no local copy yet answers that the log is not available and starts a single background clone that reaches every worker; a read-write repository that has imported nothing yet is instead left to its next sync, which creates the copy along with the first import. `InfrahubRepositoryBranchDrift` returns a row for each branch it compares, carrying the ref and the commit that branch resolves in Infrahub, together with the remote head and the condition, such as behind, rewritten, without a remote counterpart or with its tracked ref deleted upstream; the remote head and condition are read from a worker's local copy in a single request. When no worker answers in time, every branch is still listed and only the comparison with the remote is reported as unavailable. A read-only branch that has imported nothing is reported as not tracked while its ref resolves, and as ref missing once that ref is deleted upstream. A read-write branch that Git does not synchronise is left out of the rows entirely. `InfrahubReadOnlyRepositoryCheckRefs` is published alongside them so consumers can build against the full surface.
