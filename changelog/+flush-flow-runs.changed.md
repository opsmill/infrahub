Breaking: removed the `--days-to-keep` and `--batch-size` options of `infrahub tasks flush flow-runs`. The command now deletes the finished task runs older than `task_manager.retention.task_history`, with their logs and artifacts, through the task manager, and prints its progress. When `PREFECT_SERVER_SERVICES_DB_VACUUM_ENABLED` does not turn on `flow_runs`, the command deletes and rewrites nothing, prints why, and exits with code 1. On PostgreSQL, if another database session keeps a record that belongs to one of the old runs, such as a task run, log or artifact, locked for more than a minute, the command stops with an error that names the day those runs ended. Run it again once that session ends; the runs already deleted stay deleted. When the task manager database is PostgreSQL, its new `--rewrite` option then rewrites each task history and activity log table whose live rows hold less than half of its disk space, to return that space, for example after the upgrade or after lowering a retention; on SQLite it rewrites nothing. A rewrite needs free disk space for a copy of what the table keeps, and tasks that read or write a table wait while it is rewritten, for at most a minute. The command prints the tables it rewrote, the ones it left because most of their space is in use, the ones that stayed locked, the ones whose rewrite took too long, and the ones whose rewrite failed with a database error, for example when the disk has no room for the copy; after a table that stayed locked, took too long or failed, it goes on with the next one. The `infrahub-taskmanager flush flow-runs` maintenance tool passes these options too, so use a release of the tool that supports this change, and set the task history retention instead of a number of days.
