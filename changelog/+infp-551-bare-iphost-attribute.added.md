An `IPHost` attribute can now hold a bare IP address. Declaring `parameters.allow_prefix: false` on the attribute makes Infrahub store and return `10.0.0.1` instead of `10.0.0.1/32`: a redundant host mask (`/32`, `/128`) is dropped on both creation and update, and a value carrying a real subnet prefix is rejected with an error naming the attribute. The bare value is what display labels, human-friendly identifiers, uniqueness constraints, computed attributes, and the `default_value` all see, and Profiles and object templates generated from the node inherit the declaration. Derived properties are unchanged, so `prefixlen` is still `32`/`128` and IPAM prefix containment still resolves the address as a host.

An `IPHost` attribute that does not declare `allow_prefix` keeps its existing behavior, so no stored value and no existing schema needs to change. `allow_prefix` cannot be changed once the attribute exists; the documentation covers the manual recipe for converting a populated attribute. Reading a bare address attribute through the Python SDK requires SDK 1.23.0 — an older SDK re-attaches the host mask to the value.
