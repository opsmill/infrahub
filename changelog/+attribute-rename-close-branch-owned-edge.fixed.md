Renaming an attribute on a branch no longer leaves the old attribute active on nodes created on that same branch. The rename ended the old attribute by adding a deleted edge beside it, which is the only option for a node coming from the default branch, but left the branch's own edge open — so the node carried the attribute as both active and deleted. Rebasing the branch then re-ran the rename against that still-active edge and could create a second copy of the renamed attribute. The rename now closes the edges the branch owns instead of shadowing them.
