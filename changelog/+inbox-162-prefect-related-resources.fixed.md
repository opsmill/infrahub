Node mutation events touching many related nodes are no longer discarded on deployments that do not raise Prefect's related-resources limit. Infrahub assumed the larger limit the Infrahub container image configures, so anywhere that limit was left at Prefect's own default — a source checkout, a custom image, your own chart — Infrahub let events grow past what Prefect accepts and Prefect refused them without an error: the mutation succeeded, but no automation, trigger or webhook fired and nothing reached the activity feed. Infrahub now reads the limit Prefect actually enforces, however it was configured, so those events are delivered — truncated to the real limit, which is correspondingly smaller than the figure Infrahub previously assumed and Prefect never honoured. Deployments running the Infrahub image, which raises the limit explicitly, keep exactly the capacity they had. One related change: a non-numeric value for the limit is now reported at startup instead of being silently replaced, so a typo can no longer leave events being dropped in the background.
