Merging or rebasing a branch no longer starts one recompute per changed node for Python transform computed attributes. The merge now schedules a single pass per affected attribute, over the nodes that actually read a change, which keeps the time to refresh those values flat as a branch grows.

Set `INFRAHUB_COALESCE_PYTHON_RECOMPUTE_AFTER_MERGE` to `false` to go back to the previous behaviour.
