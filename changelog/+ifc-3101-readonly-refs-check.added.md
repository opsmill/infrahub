Read-only repositories are now checked for upstream movement of the refs they track, so a branch or tag that advances on the remote is noticed without waiting for someone to trigger an import. The check runs on a schedule. A user with permission to update the repository can also start it from the "Check remote now" button on the repository's Commits tab, or through the `InfrahubReadOnlyRepositoryCheckRefs` mutation, which previously accepted a request and did nothing. While an on-demand check of the repository runs, the button is disabled and links to its task. When it finishes, the Commits tab reloads and shows the new check time, even if the remote has not moved. A check pressed while a scheduled check holds the repository ends at once without recording a check time, and the new time shows once the scheduled check ends and the tab is refreshed. A repository whose tracked ref has moved has the new objects brought into every worker's copy, while the commit Infrahub has imported stays exactly where it was: nothing here writes the tracked commit, triggers an import, or changes which commit a worker has checked out.

`INFRAHUB_GIT_READ_ONLY_REFS_CHECK_INTERVAL_MINS` sets how long the system waits before checking one repository again, defaulting to 15 minutes. Lengthening it is the way to make the check less frequent; an idle repository costs one refs listing per interval and transfers nothing. A repository whose remote cannot be reached is recorded with the reason and retried sooner than a full interval, without holding up the others.
