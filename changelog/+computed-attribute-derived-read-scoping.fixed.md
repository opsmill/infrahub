Python computed attributes no longer recompute on every schema change because their transform query reads one human-friendly id or display label. The fields behind such a derived read cannot be named, so the whole read set was marked imprecise and every other kind's field list was thrown away with it. A schema change to an unrelated kind then selected the attribute and recomputed it across every node of its kind. The imprecision now stays on the kind read through the derived field: any change to that kind still counts, every other kind is filtered on the fields the query really reads.
