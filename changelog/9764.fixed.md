Added an `ordered` flag to attribute schemas. When set to `false` (the default) on a `List` or `JSON`-array attribute, reordering its elements is no longer reported as a conflict during branch merge and rebase (element counts still matter, so adding or removing an element is still a conflict). The built-in schema `enum`, dropdown `choices`, generic `used_by`, and `restricted_namespaces` attributes now use this so that two branches reordering the same list can be merged without a manual conflict resolution.
