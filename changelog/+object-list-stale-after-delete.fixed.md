Fixed deleted objects sometimes staying visible in the object, IPAM and relationship lists after the deletion succeeded. When a list refetch was already in flight at the moment of a mutation (e.g. triggered by a preceding edit), Apollo's query deduplication merged the post-mutation refetch into that in-flight request, so it adopted the pre-delete response and restored the removed rows. The list queries now disable query deduplication, matching the object-count query, so a refetch always reflects the committed state.
