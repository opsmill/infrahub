The repository page has a new Commits tab. Once Infrahub can read a repository's commit history, the tab lists the commits of the branch you are viewing, newest first, with the short hash, summary, author and date of each one. It marks the commit Infrahub has imported and the current head of the remote, shows how many commits are pending import, also as a count on the tab, and shows a notice when the tracked ref was rewritten so the imported commit is no longer part of its history. On a branch that does not sync with Git, the tab lists the history of the repository's default branch, marks the commits the branch does not run yet as "Not on this branch", counts them as not on this branch rather than pending import, and says whether a rebase of the branch brings newer commits or the branch already runs the latest one. When the default branch's history was rewritten so it no longer holds the branch's commit, the tab names that commit and asks for a rebase. A repository added on that branch keeps the pending-import wording, because a sync still imports into it until the branch is merged. The tab says when the listing was last updated, and each commit has a menu to copy its full hash or, for repositories hosted on GitHub, view the commit on GitHub.

Until Infrahub can read a repository's commit history, the tab says the commit log is not available.
