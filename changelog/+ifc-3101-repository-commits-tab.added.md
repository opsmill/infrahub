The repository page has a new Commits tab. Once Infrahub can read a repository's commit history, the tab lists the commits of the branch you are viewing, newest first, with the short hash, summary, author and date of each one. It marks the commit Infrahub has imported and the current head of the remote, shows how many commits are pending import, and shows a notice when the tracked ref was rewritten so the imported commit is no longer part of its history. On a branch that does not sync with Git, the Commits tab of a read-write repository lists the history of the repository's default branch and says, as Git does, how many commits the branch is behind it ("behind main by 2 commits") or that it is up to date, marks those commits as "Behind", and asks for a rebase of the branch to use them. When the branch has diverged from the default branch, for example after a force push, the tab shows a warning that names the commit the branch uses and asks for a rebase, and the commit labels stay as for any rewritten history ("Remote head", "Not on current history"). A repository added on that branch keeps the pending-import wording, because a sync still imports into it until the branch is merged. The tab itself carries an amber count when commits are waiting: a download icon when an import brings them and a branch icon when only a rebase does, capped at 999+ with the exact number and the next step in its tooltip. It shows a warning marker without a number when the history was rewritten, the imported commit is missing from the remote or the tracked ref was deleted, and nothing when nothing is pending. The tab says when the listing was last updated, and each commit has a menu to copy its full hash or, for repositories hosted on GitHub, view the commit on GitHub.

Until Infrahub can read a repository's commit history, the tab says the commit log is not available.
