The daily anonymous telemetry report now includes the CPU and memory available to the API server and the task workers, and the CPU count set for the database. Two new blocks, `server` and `task_workers`, count the processes of each component the same way `workers` does. Each also reports `processes_per_container`, the number of processes that share one container, and a `per_container` object with the CPU count a process in that container can use (`processor_available`), the CPU limit set on the container (`processor_assigned`), and the memory and free memory of the container (`memory_total`, `memory_available`). Multiplying `per_container` by `active` and dividing by `processes_per_container` gives the total for the component. The database block gains `processor_assigned`, the CPU count set for the Neo4j parallel query engine. The `workers` block and every other existing field are unchanged, and a new figure that cannot be read is reported as `null` without affecting the rest of the report.
