The daily anonymous telemetry payload now reports per-component CPU and memory allocation for the database, the API server, and the worker fleet. The database's `system_info` gains `processor_assigned` (the configured Cypher-parallelism limit), the existing `workers` block gains `processor_available`, `processor_assigned`, `memory_total`, and `memory_available` for the task-worker fleet, and a new top-level `server` block carries the same four fields for the API server. `processor_available` is the logical processors each component can actually use, the host's count capped by any enforced CPU limit, so the figure is comparable across components; `processor_assigned` is the enforced limit itself. Memory usage is derived as `memory_total − memory_available`. The database's `processor_assigned` reads back `null` until a core limit is configured on Neo4j, while the server and worker figures are live control-group reads that already report a number wherever a container CPU limit is set.

All changes are additive and backwards-compatible: no existing field is renamed or removed, the `payload_format` identifier is unchanged, and a figure whose source is unavailable reports `null` on its own without holding up the rest of the payload. The fleet figures behave slightly differently: when some worker hosts report and others do not, the aggregate sums the ones that did rather than reporting `null`, so it can understate a fleet that is partly silent.
