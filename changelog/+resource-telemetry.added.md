The daily anonymous telemetry payload now reports per-component CPU and memory allocation for the database, the API server, and the worker fleet. The database's `system_info` gains `processor_assigned` (the configured Cypher-parallelism limit), the existing `workers` block gains `processor_available`, `processor_assigned`, `memory_total`, and `memory_available` for the task-worker fleet, and a new top-level `server` block carries the same four fields for the API server. Memory usage is derived as `memory_total − memory_available`, and `processor_assigned` reads back `null` until a core limit is enforced.

All changes are additive and backwards-compatible: no existing field is renamed or removed, the `payload_format` identifier is unchanged, and every new figure independently reports `null` when its source is unavailable so the rest of the payload is still gathered.
