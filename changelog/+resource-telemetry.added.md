The daily anonymous telemetry report now includes the CPU and memory available to the API server and the task workers, and the CPU count set for the database. Two new blocks, `server` and `task_workers`, count the processes of each component the same way `workers` does and add a `per_worker` object with the CPU count a process can use (`processor_available`), the CPU limit set on its container (`processor_assigned`), and its total and free memory (`memory_total`, `memory_available`). Multiplying `per_worker` by `active` gives the total for the component; for API server processes that share a container, `per_worker` is the share of each. The database block gains `processor_assigned`, the CPU count set for the Neo4j parallel query engine. The `workers` block and every other existing field are unchanged, and a new figure that cannot be read is reported as `null` without affecting the rest of the report.
