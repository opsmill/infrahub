Added native Redis Sentinel support for the cache and distributed lock connections. A new `INFRAHUB_CACHE_URL` setting accepts a full Redis connection URL using the `redis://`, `rediss://`, `redis+sentinel://`, or `rediss+sentinel://` scheme. When a `redis+sentinel://` URL is configured, Infrahub discovers the current master through the listed Sentinel nodes and follows failover automatically, removing the need for a `redis-sentinel-proxy` in front of a Sentinel-managed Redis. Prefect's task result storage follows the same failover, and so do Prefect's messaging Redis and Docket, the component that coordinates Prefect's background services, when their URLs point at the Sentinel nodes. Existing single-node deployments using the scalar `INFRAHUB_CACHE_ADDRESS`/`INFRAHUB_CACHE_PORT` settings are unaffected.
