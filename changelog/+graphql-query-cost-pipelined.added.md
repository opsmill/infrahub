Added the `INFRAHUB_GRAPHQL_COST_PIPELINED_RUNTIME_FOR_HIGH_COST_QUERIES` setting, off by default: a request to a stored GraphQL query with the `high` cost level whose estimate with its variables is above `INFRAHUB_GRAPHQL_COST_HIGH_COST_DATABASE_ROWS` runs the database queries that would use the parallel Cypher runtime of Neo4j with the pipelined runtime, which uses one CPU core for each query.
