Added `INFRAHUB_DB_MAX_CONNECTION_POOL_SIZE` to bound the number of connections the Neo4j driver keeps in its pool per remote address. Every Infrahub process builds its own driver, so the total connection footprint against the database is this value multiplied by the number of server workers and task workers. Sizing it against Neo4j's `server.bolt.thread_pool_max_size` prevents the database from being asked to serve more concurrent requests than it has bolt threads for.
