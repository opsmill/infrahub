Editing a repository's `.infrahub.yml` no longer regenerates every artifact and re-run every Generator in that repository. The manifest was previously merged into every Transformation's and Generator's dependency closure, so any edit to it - including a comment-only change, or an entry belonging to an unrelated definition - matched every closure and triggered a full re-render.

The manifest is now absent from every closure. A manifest edit is a regeneration signal only through the definition field it actually changed: changing a Transformation's `template_path`, `file_path`, or `class_name`, or an artifact definition's `parameters`, `content_type`, `artifact_name`, or `targets`, still regenerates that definition's artifacts. Listing `.infrahub.yml` under a definition's `watch.files` puts it back in that definition's closure if you want the old behavior for it.

Python Transformation and Generator definition fingerprints now also include `file_path`, closing a case where repointing a definition at a different file in a watched directory left its fingerprint unchanged. Because the fingerprint composition changed, the first repository import after upgrading recomputes fingerprints for Python Transformations, Generator definitions, and Python-Transformation-backed artifact definitions. That regenerates their artifacts once, which produces no new artifact versions where the rendered output is unchanged, and re-runs each affected Generator once.
