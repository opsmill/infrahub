Generators now try to delete every node from an earlier run that the current run does not save again, including when a run saves no nodes at all. Previously, a run that saved nothing deleted nothing, and the cleanup stopped at the first node it could not delete, so nodes the generator no longer produced could stay in place. Now a node that cannot be deleted stays in the generator's group, the cleanup continues with the other nodes, and the generator run reports an error. On a branch, the cleanup deletes on that branch, and deleting a node of a branch-agnostic kind removes it from every branch, including the default branch.

Before upgrading, check generators that skip saving nodes when their inputs have not changed: those nodes are now deleted on the next run. A generator must save every node it wants to keep on every run. Nodes that a generator updates but does not own, such as a node it only adds a checksum to, should be saved with update_group_context=False so they are not added to the generator's group. A node that an earlier run already added to the group is still deleted on the first run that saves it with update_group_context=False, so remove it from the generator's group before that run.
