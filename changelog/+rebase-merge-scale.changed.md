Rebasing or merging a branch and checking a proposed change now check the rules of a changed attribute only on the objects where that attribute changed, instead of on every object of the kind, except the check that the value is unique. Rebasing a branch no longer reads every relationship in the database, and updating a branch diff reads only the changes made in the time window to list the objects with a changed attribute value or property. The first start of the Infrahub server after the upgrade creates a new database index on the branch of the relationships that record resource pool allocations, which the rebase reads; the database builds it in the background, and the rebase uses it when it is ready.
