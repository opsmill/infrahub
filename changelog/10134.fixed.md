Removing the last object file from a repository, or clearing the `objects:` list in `.infrahub.yml`, now deletes the objects that file defined. Previously an import that ended up tracking no objects at all skipped the cleanup entirely, so those objects stayed in the instance as orphans and the repository's tracking group kept listing them. Removing one object file among several already worked; only the empty case was affected.

Objects left orphaned by earlier versions are deleted on the first import after upgrading. If you worked around this by removing object files one at a time, or by keeping a placeholder object file, neither is needed any more.

An object that cannot be deleted because another node still references it through a mandatory relationship no longer aborts the rest of the cleanup. Every other object is still removed, the failures are reported together, and the objects that could not be deleted stay in the tracking group so the next import retries them. The import itself continues: menus, checks, generators and artifact definitions are still applied, and the failed deletions are reported as a warning on the import task rather than failing the repository sync.
