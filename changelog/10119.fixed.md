Creating an object now retries transient database errors the same way updates, upserts and deletes do, instead of surfacing a raw Neo4j "there are no available threads to serve this request" message when the database is briefly saturated. Retries no longer stack when one mutation calls another, so a single failing operation is attempted at most `retry_limit` times rather than that many times per layer, and profiles applied during a create are now written in the same transaction as the node itself.
