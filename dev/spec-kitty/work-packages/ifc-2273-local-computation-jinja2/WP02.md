# Work Package WP02: Inline Recomputation for Local Attribute Changes (US1 — MVP)

## Goal

Implement the core `_recompute_local_jinja2()` method and integrate it into the update path so local attribute changes trigger immediate computed attribute recomputation.

## What Was Implemented

### T005: `_recompute_local_jinja2()` on `Node`

Implemented in `backend/infrahub/core/node/__init__.py` (line 730). Key design decisions vs original plan:

- Uses `schema_branch.computed_attributes.get_local_jinja2_targets(kind, updates=fields, cascade=True)` to obtain the dependency-ordered list of local targets affected by the updated fields. The `cascade=True` flag causes the registry to walk chained dependencies via `get_local_targets_in_dependency_order()`.
- Variable resolution uses `schema_branch.validate_schema_path()` to parse template variables, supporting both attribute and relationship paths.
- Relationship variable resolution loads peers via `registry.manager.get_one_by_id_or_default_filter()` after getting the peer from `RelationshipManager.get_peer()`.

### T006: Integration into `_update()`

Called at line 1040, after the relationship save loop, before HFID recomputation:
```python
await self._recompute_local_jinja2(db=db, fields=fields, node_changelog=node_changelog, update_at=update_at, user_id=user_id)
```

### T007: Chained Dependencies

Dependency resolution is handled inside the computed attribute registry (`schema_branch_computed/jinja2.py`), not on `Node`:
- `get_local_jinja2_targets(..., cascade=True)` calls `RegisteredNodeComputedAttribute.get_local_targets_in_dependency_order()` which walks local_fields wave by wave, emitting dependency-first ordering and cascading through chained computed attributes.
- Within each wave, targets whose output triggers another wave member are emitted first; dependents are deferred to the next iteration. Cycles are broken by emitting all members.

### T008-T010: Component Tests

Tests in `backend/tests/component/computed_attribute/test_local_computation.py` (note: `component/` not `functional/`):
- `test_local_attr_change_triggers_recomputation` — updates `name`, verifies `label` recomputed
- `test_unrelated_attr_change_does_not_trigger_recomputation` — updates `description` (not referenced by the template), verifies no Jinja2 render/recomputation occurs
- `test_chained_jinja2_dependencies` — verifies `label` and `fqdn` both update when `name` changes
- `test_jinja2_error_handled_gracefully` — mocks render failure, verifies mutation succeeds with old computed value
