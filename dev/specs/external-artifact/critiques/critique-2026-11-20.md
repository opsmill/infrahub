## Executive Summary

The spec solves a clear problem: teams with templates in an external engine cannot get Infrahub artifacts without rewriting those templates. The plan reuses the existing selection, webhook, storage and check paths, and does not build a second pipeline.

Three items must be resolved before tasks:

1. Putting the query result in a readable event bypasses object permissions.
2. Concurrent callbacks, new requests and the sweep can race on the artifact's render state.
3. Validator recomputation can race when several checks finish at the same time.

Each has a contained fix.

## Engineering Lens Findings 🔬

### Architecture Soundness
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 🎯 | Render-state changes race. A callback validates render ID R. A new request then writes R2 and `Pending`. The callback then writes `Ready` with R's content, so outdated content is stored as current. The sweep and a callback can race in the same way. | Run every change to `render_request_id`, `render_deadline` and the render status under a lock per artifact and branch (`infrahub.lock` registry). Validate the render ID inside the lock. |
| E2 | 🎯 | Validator recomputation races. Several callbacks for the same validator can finish together, each read the checks before the others write, and leave the validator `in_progress` or with a wrong conclusion. | Recompute the validator under a lock per validator. Recompute from the stored checks, not from the caller's result. |

### Failure Mode Analysis
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E3 | 💡 | Delivery retries take at least 6 minutes. With a timeout below about 7 minutes, the deadline can pass while delivery is still retrying. | Document that the timeout must cover the delivery retries. Keep the minimum of 1 second for tests. |
| E4 | 💡 | If the engine's callback is shed with 429 and the engine does not retry, the render times out. | The reference engine and the docs require a retry on 429. Already in the quickstart. Add it to the user docs. |

### Security & Privacy
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E5 | 🎯 | The full query result in the event payload is readable by any user who can run the GraphQL `Events` query. Some of those users may not be allowed to read the nodes or fields the query returns. This bypasses authorization at the API layer (constitution VI). | Keep the query result in the event, as the user decided, but leave `query_result` out of the payload that the `Events` and `Task` GraphQL queries return for this event type. The Prefect UI is reachable only by operators. State that in the security notes. |
| E6 | 💡 | Content accepted through the callback has no account attached for audit. | Save artifact changes with the internal account of the task worker, and record `render_id` and the transformation name in the artifact events, so audits can trace the change to the external engine. |

### Performance & Scalability
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E7 | 💡 | The sweep runs every minute on every branch. | Filter on `render_deadline` set and earlier than now, which keeps the result small. Check whether that attribute needs an index (`dev/knowledge/backend/database-indexes.md`). |
