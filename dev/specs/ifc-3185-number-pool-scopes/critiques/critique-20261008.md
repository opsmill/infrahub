## Executive Summary

The spec states the problem from the PRD with customer evidence, keeps the contract already given to the frontend team, and records where the product owner's decisions override the sources. The plan keeps the record model untouched and puts the scoped behaviour in one module. Three points block task generation as written: the per-division lock cannot be computed where the mutation computes its lock names today; the deferral of pool allocation inside node creation is described for scoped pools only, which would create two code paths; and FR-014 (provided numbers checked per division) depends on code that is not in the working tree, so it cannot be turned into a task. All three are resolved below by edits to the plan and the spec, applied in this phase.
