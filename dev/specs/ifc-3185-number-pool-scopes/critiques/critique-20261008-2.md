## Executive Summary

The spec now describes changes to code that exists on the branch (the `allocation_scope` attribute and parameter, the attach path, the ranges allocator, the mock pull request) and records the ten decisions of the product owner. The plan names the real symbols of the allocation chain, the lock computation, the queries and the schema constraint machinery. Two points block task generation as written: the update path used to compute the mutation lock names does not resolve the pool today, so the per-division lock key the plan promises cannot be computed there without a change the plan did not name; and the stored shape of the scope changes without a migration, so the reader of the stored value must say what it does with a value in the old shape. Both are resolved below by edits to the plan, the research and the data model, applied in this phase. Three questions stay open for the product owner and are listed at the end.
