## Executive Summary

The spec states a real integrity defect with a concrete, reproduced failure (non-compliant data reaching the default
branch, and unreadable values after a kind change), and the plan builds on an implementation already exercised on a
local instance. Three items need updates before tasks. First, the plan's new way of building the merged schema
(applying the branch's diff) covers nodes and generics but says nothing about profiles, templates and attributes
inherited from generics, which the previous design handled implicitly. Second, the constitution requires Docker
integration tests for features involving schema migrations, and the one bug the in-process tests missed (kind change
and attribute class) only appeared on the distributed stack. Third, the spec introduces a refusal that the branch
cannot fix by itself, a mandatory attribute added on the default branch without a default value, but it does not
give the user a recovery path.

## Engineering Lens Findings 🔬

### Architecture Soundness
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 🎯 | The merged-schema rules (research R5, data model) apply the diff to nodes and generics only, because the schema diff covers only those. Profiles and templates are generated from nodes, and attributes inherited from a generic are matched by name with no id. The previous design copied every kind, including profiles and templates. The checks of profile or template nodes changed on the branch read their schema from the merged schema, so a stale profile or template schema would check them against the wrong rules. | Add rules: for each changed node kind, take the branch's profile and template schemas; and an inherited attribute follows its generic. Add unit cases for a generic attribute changed on the default branch, and for the profile schema of a node whose attribute changed on the branch. |
| E2 | 💡 | The gate and the merged schema both read the in-memory registry of the worker that runs the merge. The design assumes it holds the latest schema of both branches. | Add a task that confirms the merge and rebase flows refresh both branches' schemas before the checks, or refresh them explicitly. |
