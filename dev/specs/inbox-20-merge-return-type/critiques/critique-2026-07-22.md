# Critique Report: Correct merge()/rebase() return-type annotations

**Date**: 2026-07-22
**Feature**: [spec.md](../spec.md) · [plan.md](../plan.md)
**Reviewer lenses**: Product (product-lead) + Engineering (staff-engineer)

## Executive Summary

The spec and plan are **sound, accurate, and appropriately scoped** for a deliberately minimal,
annotation-only type-correctness fix. Problem is verified in source and corroborated by the
Confluence SOLID analysis (§4.2 / §9, High priority). No Must-Address items.

One material engineering nuance surfaced that the spec/plan should reflect for accuracy: the
`infrahub.git.repository` module has a **mypy override that disables the `return-value` error
code** (`pyproject.toml` `[[tool.mypy.overrides]]`, also `arg-type`, `assignment`,
`call-overload`). That suppression is the reason the annotation lie was never caught, and it means
the fix's value accrues to **external callers and human readers** (and as an enabler for a future
suppression-removal), not to in-module mypy enforcement. This refines — but does not weaken — the
rationale. Removing that suppression is a *separate* tech-debt item and is correctly out of scope.

**Verdict: ✅ PROCEED** (with two small autonomous accuracy edits applied to spec.md/plan.md; see
Remediation).

### E1 (💡 Recommendation) — mypy `return-value` is suppressed for this module

`infrahub.git.repository` disables `return-value` (and `arg-type`, `assignment`, `call-overload`)
via a `[[tool.mypy.overrides]]` block. Consequences:
- mypy did **not** flag the current lie and will **not** error on the corrected annotation either —
  so "the type gate passes" is necessary but not, on its own, proof the fix *did* anything inside
  this module.
- The fix's real value is for **callers in other modules** (checked under their own settings) and
  **human readers**, and as a prerequisite for later removing the suppression.
- **Action taken**: refine spec SC-001 and plan wording to state this honestly, and explicitly
  scope OUT removing the suppression (that is a separate mypy-burndown card).

### E2 (💡 Recommendation, low) — optional contract-locking test

Consider (optional) a focused assertion that a successful merge returns a `str` and a no-op returns
`False`, if not already covered, to lock the runtime contract independent of annotations. Not
required; existing component tests already exercise merge/rebase. No ticket ID in any test name.

## Cross-Lens Insights

### X1 (💡) — Scope boundary vs. the mypy-suppression burndown

Both lenses converge: the *tempting* adjacent work — removing `return-value` from this module's
mypy override so the annotation is actually enforced in-module — would expand the diff and likely
surface unrelated suppressed errors (`pull()` consumers, `get_commit_value`, etc.). That is a
distinct tech-debt item (the Inbox has a family of "clear mypy suppression on <module>" cards).
Keeping it out of scope reduces both risk and review burden while leaving the annotation honest for
the future removal. **Decision: stay out of scope.**
