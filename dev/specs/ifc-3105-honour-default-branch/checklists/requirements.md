- Amendment round 4 (2026-09-04), after `/speckit-analyze`: the skipped-branch warning gains a second trigger on the synchronisation carrier. It is now recorded by a run that either imported at least one branch (as before) or observed a new commit on the skipped branch itself. The previous rule was silent at the one moment the warning is most actionable, a push to the branch that is not being imported, while speaking up on cycles that imported some unrelated branch. The exclusion in round 2 rested on a premise that is wrong against the code: it claimed the last commit on an unimported branch would have to be remembered, when `fetch` uses no refspec, so the colliding branch has a remote-tracking ref whose commit the branch listing already reads. Capturing the remote heads before the fetch and comparing after it is a local ref read with no extra network call and nothing written to the graph, so no governance gate moves. Accepted cost: the comparison is per worker, so one push may be reported once per worker; deduplicating it needs shared state.
