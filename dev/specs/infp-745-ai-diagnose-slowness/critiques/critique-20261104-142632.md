## Executive Summary

The spec and the plan describe one clear workflow: the operator turns on the Grafana MCP server, a
user connects an AI assistant, and the skill writes a report with evidence. The research found the
facts that change the design: the standalone Compose file drops profiles, `mcp-grafana` 2.0.2 starts
without authentication when no token is set, and usage statistics are on by default. The plan handles
each of them.

Two items must change before tasks are written:

- **What Loki holds.** The promise is that no personal data reaches the AI model provider. But Alloy
  sends the logs of every container of the Compose project to Loki (`development/alloy/config.alloy`,
  `discovery.docker "containers"` with only a project filter): Neo4j, RabbitMQ, Redis, the Prefect
  server and its database, Grafana, and the new MCP server itself. The log audit (FR-022) covers only
  the lines that Infrahub writes.
- **Where the port listens.** Compose publishes the server as `8100:8000`, so it listens on every
  network interface of the host, over plain HTTP. The allowed hosts check reads the `Host` header,
  which the client chooses, so it does not limit who connects. The token is then the only protection,
  and it travels unencrypted.

The other findings are improvements, mostly about tests and the operator's documentation, and one
question about the scope of the first release.

## Engineering Lens Findings 🔬

### Architecture Soundness

No finding. The plan reuses the Compose profile and one-time container patterns of the stack, and the
hook Job pattern of `infrahub-helm`. Each repository gets its own pull request, in an order that
follows the dependencies (fixtures need the Compose stack; docs need the published skill).

### Failure Mode Analysis

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 💡 | The restart policy is left to implementation (`contracts/compose-settings.md`). With no `restart` key, the server does not come back after the Docker host restarts, while the rest of the stack does. With `unless-stopped`, a missing token causes a restart loop. | Make the runtime check of the two options the first task of the Compose phase, and record the result in the contract before the service is written. |
| E2 | 💡 | The Helm probes on `/healthz` depend on a side listener whose behavior is not verified (research R3). A wrong probe makes Kubernetes restart the pod in a loop. | Add a task that starts the image in kind with the probe settings before the chart templates are written. |

### Security & Privacy

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E3 | 🎯 | Compose publishes `8100:8000`, so the server listens on every network interface of the host, over plain HTTP. The allowed hosts check reads the `Host` header, which the client sets, so it is not an access control. The bearer token is the only protection and is sent unencrypted. | Publish `127.0.0.1:8100:8000` by default, which matches the default allowed hosts. Document access from another computer through an SSH tunnel or a reverse proxy with TLS. In Helm, keep a `ClusterIP` Service by default and say that an Ingress needs TLS. Change FR-006, FR-007 and `contracts/compose-settings.md`. |
| E4 | 💡 | Grafana in Compose has fixed admin credentials (`admin` / `admin`, set in the service, not from variables). The init step reads `INFRAHUB_GRAFANA_ADMIN_USER` and `INFRAHUB_GRAFANA_ADMIN_PASSWORD`, but Grafana itself does not, so the two can differ. | Make the Grafana service read the same two variables, so that one setting changes both. Say in the docs that the default password must be changed when the server is turned on. |
| E5 | 💡 | The AI assistant also reads Prometheus. The audit (FR-022) does not check metric labels, for example `query_name` and `path` of Infrahub's metrics, or the labels of the Neo4j and Prefect metrics. | Add metric labels and trace resource attributes to the audit scope in FR-022. |
| E6 | 💡 | The MCP server's own logs go to Loki (all containers do). Not checked: whether `mcp-grafana` logs the caller token, the Grafana token, or the queries it runs. | Add a check to the audit: read the server's log lines during the quickstart and confirm that no token appears. |

### Performance & Scalability

No finding. The server reads Grafana on demand and adds no work to Infrahub. A large query from the
assistant loads Prometheus, Loki or Tempo, as a person using Grafana would.
