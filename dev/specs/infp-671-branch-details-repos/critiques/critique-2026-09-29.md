# Critique Report: Branch details — Git repositories and tasks

**Date**: 2026-09-29
**Feature**: [spec.md](../spec.md)
**Plan**: [plan.md](../plan.md)
**Verdict**: ⚠️ PROCEED WITH UPDATES (all Must-Address items applied in the same run; see "Applied")

---

## Executive Summary

The spec and plan are faithful to the design handoff and unusually grounded: the research found that three of the handoff's assumptions are stale on this base (IFC-3199 isn't here, the theme is here, the object body card changed), and that the riskiest assumption from the brief — tying an import task to a repository — only half holds (`git-repository-import-object` isn't tagged with the repository). The plan contains that risk well: the band comes from `sync_status`, not from the task. Two Must-Address items were found. First, FR-031 as written ("Merge MUST NOT be disabled … because of task states") contradicts today's `BranchMergeButton`, which disables Merge while a merge of the branch is already running; implemented literally it would remove a real guard. Second, the page reads the **page's** branch but the plan's links use `constructPath`, which forwards the **selector's** branch: "Open in Tasks", the repository links and "Open repository" would open the wrong branch whenever the two differ (Principle II). Recommendations cover polling cost, page-drift while paging, the failed-count semantics, and a post-launch check now that the brief's success measure no longer applies.
