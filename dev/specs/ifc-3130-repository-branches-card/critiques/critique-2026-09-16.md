## Executive summary

**Verdict: ⚠️ PROCEED WITH UPDATES.** The plan is better than average — the reuse sweep is real, D2's
mock-boundary insight is correct and load-bearing, D3's three-layer pagination is the right shape, the
`node_metadata` omission is a genuine structural guarantee rather than a claim, and the two
"verified by review" admissions are honest rather than evasive. **Nine of eleven source claims checked
hold exactly as written.**

It is nonetheless **not ready to start**, for seven must-address defects. Three of them sit on the
feature's core value and were found only by checking source:

- **E2** would ship a branch-scoped card that **omits `commit` and `sync_status`** on the read-write
  kind — inverting the feature's entire purpose.
- **E3** means the central architecture decision (D1) names a component that **cannot produce the
  specified UI**.
- **E5** means the only *mechanical* guarantee in the plan (FR-017's zero-diff check) is **vacuous** —
  it names a path that does not exist, and `git diff --exit-code` with a pathspec matching nothing
  exits 0 forever.

Plus two documentation defects that misstate the backend contract (**E1**) and understate how far the
feature diverges from the design canvas (**P1**).

None requires a redesign. All are document edits plus two conversations — one with the designer, one
with the epic owner.

**Recommended gate**: work units 1, 2 and 4 may start now. Hold units 3, 6 and 7 until E2, E3 and E4
are resolved. Land E13's pairing helper inside unit 4 **before any card test is written** — it is the
one decision that cannot be retrofitted cheaply.

## Verified as correct — recorded so they are not re-litigated

The engineering lens checked eleven source claims. **Nine hold exactly as written:**

- `DataTable`'s count footer when `count !== undefined` (`data-table.tsx`); `T extends NodeCore`
  with `getRowId: (row) => row.id` (:44, :64); default grid reserving a trailing `2.5rem` actions
  column (:41-42). **All three of corrections 2 and the gridTemplateColumns note are correct.**
- `renderAt` is private to `link-tab.test.tsx` and **does** override the whole wrapper — `render.tsx`
  spreads `...options` after `wrapper`, so the caller's wrapper wins. **Correction 1 correct.**
- `isOfKind` resolves through `inherit_from` (`is-of-kind.ts`), same predicate as
  `object-details-tabs.tsx`. **Correction 4 correct — no kind list needed.**
- `DropdownCell` requires a non-null value and computes text colour with `lch(from …)`.
- Branch-support metadata is client-side on all five attribute reads **and** on `RelationshipSchemaRead`,
  with required node-level `branch`. **FR-019's premise holds** (its value *mapping* does not — E2).
- `usePagination` is hard-wired to global `QSP.PAGINATION`, `DEFAULT_LIMIT = 10`; `Pagination` takes
  only `{count?, className?}`. **The complexity justification for a second mechanism is fully earned.**
- `ERROR_CODES.PERMISSION_DENIED` with typed `PermissionDeniedData` exists; `client.ts` does rethrow
  a bare `Error` with detail on `.cause`. **D4's premise is sound.** Bonus: `hasCatalogueCode` /
  `parseCatalogueError` (`error-handling.ts`) already exist — the use case should reuse them
  rather than re-parse `extensions`.
- Every reuse-inventory component exists at its stated path; `Content.CardTitle`'s props are exactly
  as documented.
- `shard_branches_repo` is a registered shard and the one-marker-per-file collection hook is real.

**Risk 2 is better handled than it looks.** `render.tsx` mounts `NuqsAdapter` *outside* `BrowserRouter`,
which reads like a latent crash. It is not: `createAdapterProvider` only puts the hook into context;
`useNavigate`/`useSearchParams` execute in the consuming component, inside the Router. The `afterEach`
reset is the right fix — with two refinements: also reset `window.location.search` (not just
`history.state`), and do it in a **shared setup file** so a new test file cannot silently opt out.

**Also well handled** (product lens): denied-vs-empty as separate components (FR-023/SC-007) is exactly
right; the schema-driven split genuinely makes future attributes free; the origin-branch vs
default-branch backend contradiction is flagged and correctly deferred; correction 2 prevents a
duplicated total.

## Cross-lens convergence

Where both reviewers landed on the same thing independently — the highest-signal items:

| Item | Product framing | Engineering framing |
|---|---|---|
| **The preview window is unresolved** (P5 / E19) | Fabricated values reaching a human is a trust problem; the spec forbids a UI marker while the backend's own description carries one | If IFC-3127 slips past a release, plausible fake hashes ship with nothing marking them |
| **The design divergence register is incomplete** (P1, P2 / E1) | The canvas says one card; the spec builds two and calls paging its only divergence | The contract document itself names a canvas label (`Import status`) the feature will never render |
| **A guarantee stated is not a guarantee enforced** (P4, P7 / E5, E13) | "Raise it on T094" and the success criteria are checkboxes with no owner or trigger | FR-017's zero-diff check is vacuous; D2's pairing rule is prose-only |

The convergence is a single pattern: **this plan is strong on analysis and weak on enforcement.** Its
best insights (D2's pairing rule, FR-017's zero-diff, the T094 escalation) are all recorded as prose
that a busy implementer can skip with nothing failing. The cheapest high-value change in this whole
critique is to convert three of them into mechanisms — a helper signature, a CI step, and a dated
conversation.
