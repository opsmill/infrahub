# Implementation Plan: Branch Freeze (MERGED Status)

**Branch**: `ifc-2184-branch-merged-status` | **Date**: 2026-04-24 | **Spec**: [spec.md](spec.md)

> **Note**: This feature is fully implemented. This plan is a retrospective record of architectural decisions, design contracts, and source layout.

## Summary

Introduce a terminal `MERGED` branch status that is set atomically at the end of a successful merge operation. Once set, the branch becomes read-only: all data/schema mutations, rebase, and re-merge attempts are rejected across GraphQL middleware, REST endpoints, individual mutation handlers, and the permission system. The UI reflects the status with a badge and disabled action buttons.

## Technical Context

**Language/Version**: Python 3.12 (backend), TypeScript 5.9 (frontend)

**Project Type**: Web application (backend + frontend)

**Constraints**: Status transition must be atomic with the final merge step; failure must leave branch OPEN
**Scale/Scope**: Applies to all branches; check is O(1) against in-memory branch registry

## Phase 0: Research

*See [research.md](research.md) for full decision log.*

Key decisions:
1. Reuse existing `NEED_REBASE` middleware pattern for `MERGED` rather than a new intercept layer.
2. Consolidate `check_needs_rebase_status` and `check_merge_status` into one `BranchStatusChecker` class.
3. Handle branch-delete allowance via middleware allowlist, not via a permission system carve-out.
4. Set MERGED status as the **final** step of `merge_branch()` — failure at any earlier step leaves the branch OPEN.
5. Reuse existing `cancel_proposed_changes_branch()` workflow for open PC cancellation.
6. No backfill migration for branches merged before this feature.

## Phase 1: Design & Contracts

*See [data-model.md](data-model.md) for entity model.*

### GraphQL Contract

```graphql
# Existing Branch type — no new fields; status enum extended
enum BranchStatus {
  OPEN
  NEED_REBASE
  NEED_UPGRADE_REBASE
  DELETING
  MERGED          # NEW
}

# Error response for mutations on MERGED branch
type MutationError {
  message: String!  # "Branch 'name' has been merged and is read-only."
  code: String!     # "VALIDATION_ERROR"
}
```

### REST Contract

```text
POST /api/schema/load?branch=<merged-branch>
→ 422 Unprocessable Entity
  {"detail": "Branch 'name' has been merged and is read-only."}

POST /api/artifact/generate?branch=<merged-branch>
→ 422 Unprocessable Entity
  {"detail": "Branch 'name' has been merged and is read-only."}
```

### Permission Contract

```text
GET /api/permissions/<node-kind>?branch=<merged-branch>
→ {
    "create": "DENY",
    "update": "DENY",
    "delete": "DENY",  # for non-Branch nodes
    "view":   <actual permission>
  }

# Branch node itself:
  "delete": <actual permission>  # NOT auto-denied — handled by middleware
```
