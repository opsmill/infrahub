# Critique Report: Number pool create and edit forms with weighted ranges

**Spec**: [spec.md](../spec.md) · **Plan**: [plan.md](../plan.md) · **Date**: 2026-10-08

## Executive Summary

The spec and plan are consistent and grounded in the code of this branch. One item must be addressed before tasks: the existing form and its e2e test support pools whose node kind is a generic, and the scope rule is written only for node kinds. The other findings are recommendations that tighten validation, cache invalidation and documentation. Verdict: **PROCEED WITH UPDATES**.

## Engineering Lens Findings

### Architecture Soundness

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 🎯 | `test_create_number_pool_for_generic_schema` shows a pool can target a **generic** kind. `getScopeCandidates(nodeSchema, …)` and the data model speak of a "node schema" only; `ModelSchema` includes `GenericSchema`, and `useSchema` must resolve a generic. | Type the rule on `ModelSchema` (generic or node), add a unit test with a generic schema, and add a scope-field component case for a generic kind. |
| E2 | 💡 | The plan uses one "integer" notion without a definition; `Number("1e3")`, `"1.0"`, `" 12 "` would pass a naive check. | Define parsing in data-model: trimmed string matching `^-?\d+$`, within `Number.MAX_SAFE_INTEGER`. |

### Failure Mode Analysis

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E3 | 💡 | Network failure mid-sequence is handled the same as a refusal only if the use-case catches every rejection type. | State in plan: any thrown error stops the sequence and is reported with the applied count; non-GraphQL errors show a generic message. |
| E4 | 💡 | Stale baseline (P6): deleting a range already deleted by someone else returns an error. | Covered by FR-009 reload; add a component test case "delete of a missing range". |
