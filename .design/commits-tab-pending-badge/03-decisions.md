# Decisions

- **One kind of count per tab.** The badge shows either "pending import" (an import brings the commits) or "not on this branch" (only a rebase brings them), never both: the backend picks one case per repository and branch (`_resolve_remote_branch` in #11169).
- **"Not on this branch" includes commits the default branch has not imported yet** (declined round-1 note 1, decided by Paul Leménager on 2026-10-23). On a branch that does not sync with Git, a rebase brings only the default branch's commit, so commits not yet imported on the default branch need its next sync first. Accepted: the default branch syncs on its own within about a minute, and splitting the count needs a backend change and a more complex badge.
- **Wording: "behind main", not "not on this branch"** (requested by the user, 2026-10-23). The count meaning, the row badge ("Behind") and the header lines follow Git's own wording and name the tracked ref (`git_ref`, for example `main`), not "the default branch". The same strings go into [opsmill/infrahub#11189](https://github.com/opsmill/infrahub/pull/11189).
- **Scenario B5 shows "behind" and "pending import on main" together, as an option only** (requested by the user, 2026-10-23). The prototype shows the split in every direction except `today`. Showing it in the product needs a backend change: the API counts all 3 commits as `NOT_ON_BRANCH` today. It supersedes nothing yet: the decision above (accept the overlap and show 3 behind) stands until the user picks.
