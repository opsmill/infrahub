This guide shows you how to create and apply profiles to ensure consistent configuration across multiple nodes in Infrahub. You'll learn how to create a profile, apply it to nodes, and override profile values when needed.

## What you'll achieve

By following this guide, you'll:

- Create a profile that defines standard configuration for network interfaces
- Apply the profile to multiple interfaces to ensure consistency
- Learn how to override profile values for specific interfaces
- Understand how profile inheritance works in Infrahub

## Prerequisites

- Infrahub instance running and accessible
- Schema loaded with nodes that support profiles (the schema in this guide includes an `InfraInterface` node)
- Access to GraphQL API or Python SDK (profiles are currently only manageable via API)
- Basic understanding of GraphQL mutations and queries

## Step 1: Create an interface profile

Create a profile that defines the standard configuration for end-user interfaces. This profile will set common attributes that all end-user interfaces should have.

<Tabs>
<TabItem value="graphql" label="GraphQL">

```graphql
mutation {
  ProfileInfraInterfaceCreate(
    data: {
      profile_name: {value: "end-user-interface"},
      status: {value: "active"},
      enabled: {value: true},
      auto_negotiation: {value: true},
      mtu: {value: 1500},
      mode: {value: "access"},
      untagged_vlan: {value: 10},
      role: {value: "end_user"},
    }
  ) {
    ok
    object {
      id
      profile_name {
        value
      }
    }
  }
}
```

</TabItem>
<TabItem value="python" label="Python SDK">

```python
from infrahub_sdk import InfrahubClient

client = InfrahubClient()

profile = client.create(
    kind="ProfileInfraInterface",
    profile_name="end-user-interface",
    status="active",
    enabled=True,
    auto_negotiation=True,
    mtu=1500,
    mode="access",
    untagged_vlan=10,
    role="end_user"
)
profile.save()
```

</TabItem>
</Tabs>

The profile defines these standard settings:

- **Status**: active (interface is operational)
- **Enabled**: true (interface is administratively up)
- **Auto negotiation**: enabled
- **MTU**: 1500 bytes
- **Mode**: Access (not trunk)
- **Untagged VLAN**: 10
- **Role**: end-user

## Step 3: Create interfaces using the profile

Create multiple interfaces that inherit configuration from the profile. You only need to specify the interface name and reference the profile.

<Tabs>
<TabItem value="graphql" label="GraphQL">

```graphql
mutation {
  int0: InfraInterfaceCreate(
    data: {
      name: {value: "GigabitEthernet0/0/0"}, 
      profiles: [{id: "end-user-interface"}]
    }
  ) {
    ok
    object {
      id
    }
  }
  int1: InfraInterfaceCreate(
    data: {
      name: {value: "GigabitEthernet0/0/1"}, 
      profiles: [{id: "end-user-interface"}]
    }
  ) {
    ok
    object {
      id
    }
  }
  int2: InfraInterfaceCreate(
    data: {
      name: {value: "GigabitEthernet0/0/2"}, 
      profiles: [{id: "end-user-interface"}]
    }
  ) {
    ok
    object {
      id
    }
  }
}
```

</TabItem>
<TabItem value="python" label="Python SDK">

```python
# Get the profile
profile = client.get(kind="ProfileInfraInterface", id="end-user-interface")

# Create interfaces with the profile
for i in range(3):
    interface = client.create(
        kind="InfraInterface",
        name=f"GigabitEthernet0/0/{i}",
        profiles=[profile]
    )
    interface.save()
```

</TabItem>
</Tabs>

## Step 4: Verify profile inheritance

Check that the interfaces inherited values from the profile. The metadata shows which values came from the profile.

<Tabs>
<TabItem value="graphql" label="GraphQL">

```graphql
query {
  InfraInterface(name__value: "GigabitEthernet0/0/0") {
    edges {
      node {
        name {
          value
          is_from_profile
        }
        status {
          value
          is_default
          is_from_profile
          source {
            id
            display_label
          }
        }
        mtu {
          value
          is_from_profile
        }
        enabled {
          value
          is_from_profile
        }
      }
    }
  }
}
```

</TabItem>
<TabItem value="python" label="Python SDK">

```python
interface = client.get(
    kind="InfraInterface", 
    name__value="GigabitEthernet0/0/0",
    include=["status", "mtu", "enabled"]
)

print(f"Interface: {interface.name.value}")
print(f"  Name from profile: {interface.name.is_from_profile}")
print(f"  Status: {interface.status.value} (from profile: {interface.status.is_from_profile})")
print(f"  MTU: {interface.mtu.value} (from profile: {interface.mtu.is_from_profile})")
```

</TabItem>
</Tabs>

Expected results:

- `name.is_from_profile`: False (name was explicitly set)
- `status.is_from_profile`: True (inherited from profile)
- `mtu.is_from_profile`: True (inherited from profile)
- `status.source.id`: Shows the profile that provided the value

## Step 5: Override profile values

Create an interface with a custom MTU value that overrides the profile default:

<Tabs>
<TabItem value="graphql" label="GraphQL">

```graphql
mutation {
  InfraInterfaceCreate(
    data: {
      name: {value: "GigabitEthernet0/0/3"}, 
      mtu: {value: 9000},  # Override profile MTU
      profiles: [{id: "end-user-interface"}]
    }
  ) {
    ok
    object {
      id
    }
  }
}
```

</TabItem>
<TabItem value="python" label="Python SDK">

```python
profile = client.get(kind="ProfileInfraInterface", id="end-user-interface")

# Create interface with custom MTU
interface = client.create(
    kind="InfraInterface",
    name="GigabitEthernet0/0/3",
    mtu=9000,  # Override profile MTU
    profiles=[profile]
)
interface.save()
```

</TabItem>
</Tabs>

## Validation

Your interfaces are now configured with consistent settings from the profile:

✓ All end-user interfaces have the same base configuration
✓ You can see which values come from profiles using metadata
✓ Individual interfaces can override profile values when needed
✓ Changes to the profile automatically propagate to all interfaces using it

## Advanced usage

### Using multiple profiles

Nodes can have multiple profiles assigned. Use `profile_priority` to control which profile takes precedence:

```graphql
mutation {
  ProfileInfraInterfaceCreate(
    data: {
      profile_name: {value: "high-speed-interface"},
      profile_priority: {value: 500},  # Lower number = higher priority
      speed: {value: 10000},
      mtu: {value: 9000}
    }
  ) {
    ok
  }
}
```

### Updating profiles

When you update a profile, all nodes using it automatically inherit the changes:

```graphql
mutation {
  ProfileInfraInterfaceUpdate(
    data: {
      id: "end-user-interface",
      untagged_vlan: {value: 20}  # Change VLAN for all interfaces
    }
  ) {
    ok
  }
}
```
