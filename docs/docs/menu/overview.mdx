Infrahub lets you control the menu on the left side of the web interface.

The menu has two sections. The bottom section is fixed — it lists navigation for built-in Infrahub features. The top section is user-controlled: organize your schema's node types in the order that makes sense for your use case, with custom groupings and icons.

By default, nodes without a menu placement are grouped under **Other**.

## Prerequisites

- A running Infrahub instance

## Define a menu file

A menu file is a YAML file with a defined structure. See the [menu file reference](../reference/menu.mdx) for the full schema.

Icons support any entry from the [Material Design Icons](https://icon-sets.iconify.design/mdi/) library on iconify.design.

An [Infrahub skill](https://github.com/opsmill/infrahub-skills) called `/infrahub-menu-creator` can generate this file for you. For production-grade examples, see the menus in [infrahub-demo-dc](https://github.com/opsmill/infrahub-demo-dc/blob/main/menus/menu-full.yml) and [infrahub-solution-ai-dc](https://github.com/opsmill/infrahub-solution-ai-dc/blob/main/menus/menu.yml).

The following example defines two top-level sections — Location and Infrastructure. Adjust namespaces and kinds to match your schema:

```yaml
# yaml-language-server: $schema=https://schema.infrahub.app/infrahub/menu/latest.json
---
apiVersion: infrahub.app/v1
kind: Menu
spec:
  data:
    - namespace: Location
      name: Mainmenu
      label: Location
      icon: "mingcute:location-line"
      children:
        data:
          - namespace: Location
            name: Country
            label: Countries
            kind: LocationCountry
            icon: "gis:search-country"

          - namespace: Location
            name: Site
            label: Sites
            kind: LocationSite
            icon: "ri:building-line"

    - namespace: Infrastructure
      name: Mainmenu
      label: Infrastructure
      icon: "mdi:domain"
      children:
        data:
          - namespace: Network
            name: Device
            label: Devices
            kind: NetworkDevice
            icon: "mdi:router"

          - namespace: Network
            name: Interface
            label: Interface
            kind: NetworkInterface
            icon: "mdi:ethernet"
```

:::info

For complex schemas, split menu definitions across multiple files — the same pattern used for schema files. By convention, keep them in a `menus/` folder; you can then pass the folder path to `infrahubctl menu load` to load all files at once.

:::

## Load a menu file

:::info

Use `infrahubctl` for development and testing. The git integration option is better suited for production.

:::

When you load a menu file, Infrahub creates the items that do not exist yet and updates the ones that do, matching each item on its namespace and name. `infrahubctl menu load` never deletes an item: if you remove an entry from the file and load the file again, the item stays in the menu and the command still reports success. To remove an item from the menu, see [Remove menu items](#remove-menu-items).

## Remove menu items

How you remove a menu item depends on how it was loaded. An item loaded with `infrahubctl` stays until you delete it with `infrahubctl`, GraphQL, or the Python SDK. For an item loaded from a repository's `.infrahub.yml`, Infrahub deletes it on the next import after you remove it from the menu file.

Menu items exist per branch. Delete an item on the branch where you loaded it. If that branch has since been merged, the item also exists on the branch it was merged into, so delete it there too.

Menu files have no `state` key. `state: absent` applies to [schema files](../schema/migration.mdx) only. Loading a menu file that sets `state` on an item fails with `state is not a valid attribute or relationship for CoreMenuItem`.

<Tabs groupId="method" queryString>
  <TabItem value="infrahubctl" label="infrahubctl" default>

The `infrahubctl object get` and `infrahubctl object delete` commands require `infrahubctl` 1.20 or later.

1. List the menu items on the branch:

   ```bash
   infrahubctl object get CoreMenuItem --branch <branch>
   ```

2. Find the item to remove. Each item is identified by its namespace and name, the same two values as in the menu file.

3. Delete the item, passing the namespace and name separated by `/`:

   ```bash
   infrahubctl object delete CoreMenuItem Location/Mainmenu --branch <branch>
   ```

   The command asks for confirmation. Add `--yes` to skip the prompt.

4. Delete the item's children as well. When you delete a parent item, Infrahub does not delete its children: they stay without a parent, and the web interface shows each of them as a top-level item in the menu. Run the delete command once for each child, for example `Location/Country` and `Location/Site`.

5. Reload the web interface and check that the items are gone from the menu.

See [Manage objects from the command line](../objects/manage-from-cli.mdx) for the other `infrahubctl object` options.

  </TabItem>
  <TabItem value="graphql" label="GraphQL">

Delete an item with the `CoreMenuItemDelete` mutation, identifying it by namespace and name:

```graphql
mutation {
  CoreMenuItemDelete(data: { hfid: ["Location", "Mainmenu"] }) {
    ok
  }
}
```

Run the mutation on the branch where the item exists. As with `infrahubctl`, children of the deleted item are not deleted, so run the mutation for each child as well. Infrahub refuses to delete protected items, which are the built-in items in the `Builtin` namespace.

  </TabItem>
  <TabItem value="sdk" label="Python SDK">

Fetch the item by namespace and name, then delete it:

```python
item = client.get(kind="CoreMenuItem", hfid=["Location", "Mainmenu"], branch="<branch>")
item.delete()
```

Children of the deleted item are not deleted, so repeat this for each child.

  </TabItem>
  <TabItem value="git" label="Git integration">

Remove the item from the menu file, commit the change, and push it to the remote repository. On the next import, Infrahub deletes the items that this repository loaded earlier and that are no longer in any of its menu files.

When the next import runs depends on the repository type:

- For a read-write repository, Infrahub imports the repository again when its background sync pulls a new commit from the remote.
- For a read-only repository, Infrahub imports the repository again only when you change its commit or ref, or run [Import latest commit](../git-integration/connect-repository.mdx#import-latest-commit).

Infrahub only deletes items that the repository itself loaded. An item loaded with `infrahubctl` stays until you delete it with the steps in the **infrahubctl** tab.

If the menu files no longer contain any items at all, for example after you remove the last entry or the whole `menus` list, Infrahub deletes nothing on that import and the items stay. Delete them with `infrahubctl`, GraphQL, or the Python SDK.

  </TabItem>
</Tabs>

## Good practices

### Disable schema-driven menu entries

The schema's `include_in_menu` flag provides basic menu control. When you introduce a custom menu file, set it to `false` on every node and generic — otherwise the schema and the menu file both drive the same entries, which can produce unexpected behavior.

```yaml {4}
nodes:
  - name: Node
    namespace: Example
    include_in_menu: false
```

### The IPAM section is built in

If your schema includes nodes that inherit from `BuiltinIPPrefix` or `BuiltinIPAddress`, Infrahub automatically adds an IPAM section to the menu. You do not need to define it in your menu file.

## Search anywhere

Beyond the menu, you can jump directly to any object, schema, or page from a single search dialog.

Press `Cmd+K` (macOS) or `Ctrl+K` (Windows and Linux) anywhere in the web interface to open it, then start typing. The dialog searches across objects, attributes, schemas, menu items, and documentation. You can also open it from the **Search** button at the top of the left menu, which shows the keyboard shortcut.
