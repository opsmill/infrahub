To see Infrahub in action, you have several options. Depending on your available time and preferred learning style, you can choose from the following — ranging from the quickest to the most in-depth experience:

- **[Infrahub Sandboxes](#infrahub-sandboxes)** - Public instances of Infrahub, one for each demo, that you can explore right now.
- **[Getting started lab](#getting-started-lab)** - Interactive lab that covers the basic concepts of Infrahub.
- **[Videos](#videos)** - A series of short videos that provide an overview of Infrahub and its capabilities.
- **[Infrahub demos](#infrahub-demos)** - Infrahub projects for specific kinds of networks, which you run on your own machine and, for some, open as a sandbox.
- **[Meeting OpsMill](#meeting-opsmill)** - Book a session with OpsMill to discuss your use case.

:::note

If you are looking to build your own Infrahub instance, head to the [Quick Start](./quickstart.mdx) or [Next steps](./next-steps.mdx) section.

:::

## Infrahub demos

Each demo is an Infrahub project for one kind of network: a schema, example data and Generators, with documentation that walks through the workflow. Run a demo on your own machine from its GitHub repository to change it, or open its sandbox, where there is one, to try it in your browser. OpsMill and the community develop and maintain these demos.

### AI Data Center

A reference design for large data center fabrics, such as AI data centers, where every fabric, pod and rack is built from the same design. Infrahub generates the switches, cabling, IP addresses and configurations from how many switches each level has and which switch model fills each role.

The demo includes:

- A five-stage Clos fabric in three levels: the fabric with its super spine switches, pods with spine switches, and racks with leaf switches
- Four Generators: three that build the fabric, its pods and its racks in turn, and one that adds EVPN/VXLAN overlay services for each tenant
- Configurations for Cisco, Arista, Dell and Juniper switches, rendered from the same design
- Four example fabrics, one for each vendor

[AI Data Center reference design documentation]($(base_url)infrahub-solution-ai-dc/solution-ai-dc/overview) · [AI Data Center sandbox]($(base_url)sandboxes/demo-ai-dc)

### Data Center

A spine-leaf data center modeled in Infrahub, for teams that want every new data center built from the same standard designs. Request a data center from a design and a location, and Infrahub generates its devices, cabling, IP addresses and configurations for you to review before the change is merged.

The demo includes:

- A schema for spine-leaf fabrics, VXLAN/EVPN overlays, points of presence, security zones and load balancers
- Topology designs, from which a Generator creates the devices, interfaces, IP addresses and BGP sessions
- Changes made on a branch and reviewed in a Proposed Change, with the diff, validation checks and regenerated artifacts, before they are merged
- Firewall policies modeled independently of each vendor's configuration syntax
- Configuration templates for Arista, Juniper, Cisco and SONiC
- Deployment of the generated configurations to a virtual lab with Containerlab
- A service catalog: a web form for requesting a new data center

[Data Center demo documentation]($(base_url)demo-dc) · [Data Center sandbox]($(base_url)sandboxes/demo-dc)

### Service Provider

A multi-vendor MPLS backbone and the customer services that run over it, for service providers that provision each L3VPN or SD-WAN service from a single request. Infrahub generates the VRF, interfaces, IP addresses, BGP sessions and router configurations for each service.

The demo includes:

- A schema for L3VPN and SD-WAN services, with uniqueness constraints, parent and child relationships, vendor and topology choices, and a lifecycle status
- Generators that create the VRF, route targets, PE-CE interfaces, IP addresses from resource pools and eBGP sessions from one service object
- Configurations rendered from the same service for Arista EOS, Cisco IOS-XR, Juniper Junos, Nokia SR OS, Cisco Viptela and Versa VOS
- A request workflow: the service catalog form creates a branch, the Generator runs, Infrahub regenerates the artifacts, and a Proposed Change with validation checks is opened for review before the change is merged
- A service catalog: a web application for requesting L3VPN and SD-WAN services
- Deployment of the backbone to a virtual lab with Containerlab

[Service Provider demo documentation]($(base_url)infrahub-demo-sp) · [Service Provider sandbox]($(base_url)sandboxes/demo-sp)

### Arista AVD

A reference design for Arista data center fabrics that runs Arista AVD inside Infrahub, for teams that use AVD and want a source of truth, a web interface and branch-based review around it. Infrahub generates the switches, cabling, IP addresses and BGP settings from the fabric design, and PyAVD generates the EOS configurations and documentation from that data.

The demo includes:

- A schema for fabrics, pods, racks and devices, IP prefixes and addresses, EVPN VRFs, VLANs and switched virtual interfaces, and MLAG domains
- Generators that create the super spine, spine and leaf switches, allocate loopback, interconnect and management addresses, BGP ASNs and node IDs, cable the devices, and then build the PyAVD input and structured configuration of each device
- EOS configurations, Markdown documentation for each device and fabric, and a cabling plan, rendered as artifacts
- A service portal for adding a network segment, a server or an EVPN tenant, each opened as a Proposed Change for review
- Access to the fabric data through the Infrahub web interface, the GraphQL API and the MCP server
- Deployment of the configurations through an Ansible runner or CloudVision

[Arista AVD reference design documentation]($(base_url)arista-avd) · [Arista AVD sandbox]($(base_url)sandboxes/demo-arista-avd)

### Optical transport (OTN)

A European research-network optical core modeled down to the fiber span and the wavelength, for transport engineers who need to know what runs over a fiber, what a fiber cut takes down and where the next wavelength fits.

The demo includes:

- A schema for the optical plant and the spectrum: conduits, fiber spans, optical multiplex sections, ROADMs, amplifiers, transponders, mux/demux, regenerators, the DWDM frequency grid and the CWDM wavelength plan
- Provisioning from one service object: Generators choose the route and the optical mode, allocate a position on the grid, and create the carriers, ports and client mappings
- A link budget calculated from the modeled plant, with loss, OSNR, dispersion and latency over the spans and amplifiers, and Checks that fail a service whose link budget is not met
- Impact analysis: for a fiber section, the wavelengths, capacity, services and customers that use it, and the conduits each span shares
- Capacity planning: free spectrum shown as blocks, and how many of the 96 grid anchors can take another carrier in each optical mode
- Diversity validation based on shared conduits, so two services that run through the same duct are not reported as diverse
- Network and ODU maps rendered as artifacts on each branch

[Optical transport demo documentation]($(base_url)demo-otn)

### Service Catalog

A fictional internet service provider that delivers dedicated internet access through a service catalog, so that the service delivery team requests services through a web form without involving network architects in each request.

The demo includes:

- The service modeled in the schema, and a Generator that builds each service from its request
- A web application, built with Streamlit, where the service delivery team requests a service
- A [blog post](https://opsmill.com/blog/how-to-turn-your-source-of-truth-into-a-service-factory/) about the business case

[Service Catalog demo documentation]($(base_url)demo-service-catalog)
