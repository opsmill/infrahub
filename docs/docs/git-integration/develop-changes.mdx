You change the schemas, objects, Transformations, Generators and other [`.infrahub.yml`](./infrahub-yml.mdx) content of an instance in Git. You then test the change on an Infrahub branch, and merge it into `main` of the instance through a [Proposed Change](../proposed-changes/overview.mdx). You never change `main` directly, because an import can fail, and you cannot undo a failed import on `main`.

The steps depend on the type of the repository:

- With a [read-write repository](#with-a-read-write-repository), the recommended type from Infrahub 1.12, the instance imports your Git branch by itself. When a reviewer merges the Proposed Change, Infrahub merges the Git branch and pushes it.
- With a [read-only repository](#with-a-read-only-repository), you point an Infrahub branch at your Git branch through the `ref` of the repository, and you merge the Git branch on your Git host.

The example on this page adds a `color` attribute to the built-in Tag. To promote the change to other instances afterwards, follow [promote changes between environments](./promote-between-environments.mdx).

## With a read-write repository

### Prerequisites

- An instance with the repository connected as a read-write repository. Its default branch is the Git branch that the instance imports into `main`, `develop` in this example. [Connect a repository](./connect-repository.mdx) describes how.
- If the instance has an import filter, `INFRAHUB_GIT_IMPORT_SYNC_BRANCH_NAMES`, a filter that matches your branch name, such as `["feature/.*"]`. [Branch synchronization](./branch-synchronization.mdx) describes the filter.
- A local checkout of the repository with permission to push branches.

### Step 1: Create the change in a Git branch

Create a feature branch from the default branch, add a schema file that adds a `color` attribute to Tag, then commit and push it:

```bash
git fetch origin
git switch -c feature/add-tag-color origin/develop
mkdir -p schemas
cat > schemas/tags.yml <<'EOF'
---
version: '1.0'
extensions:
  nodes:
    - kind: BuiltinTag
      attributes:
        - name: color
          kind: Text
          optional: true
EOF
git add schemas/tags.yml
git commit -m "Add color attribute to Tag"
git push -u origin feature/add-tag-color
```

The `schemas` list in `.infrahub.yml` must include `schemas/tags.yml`, so that Infrahub imports the file.

You can also create the branch on the instance, with **Sync with Git** turned on. Infrahub then creates the Git branch, and you push your commits to it.

### Step 2: Test the change on the Infrahub branch

Infrahub checks Git for new branches and commits once a minute. It imports `feature/add-tag-color` as an Infrahub branch with the same name, and imports each commit that you push to it.

On the Infrahub branch, check that the schema of Tag has the `color` attribute. To change the schema, push another commit and wait for the import.

Objects that you create on the Infrahub branch also merge into `main` with the Proposed Change. Delete test objects before you merge.

### Step 3: Merge the change into `main`

1. Open a Proposed Change from `feature/add-tag-color` to `main` and review it.
2. Merge the Proposed Change. Infrahub merges the Git branch into `develop` and pushes `develop`.

With `INFRAHUB_DELETE_BRANCH_AFTER_MERGE` and `INFRAHUB_GIT_DELETE_GIT_BRANCH_AFTER_MERGE` set to `true`, Infrahub also deletes the branch in Infrahub and in Git.

## With a read-only repository

A read-only repository imports only the Git branch named in its `ref`, and only when you run **Import latest commit** or change the `ref`. The `ref` is recorded per Infrahub branch. You import your Git branch onto an Infrahub branch by changing the `ref` on that Infrahub branch only, so `main` stays unchanged.

Steps 1 to 5 of the diagram develop a change on the development instance. Hover over a step to show only that step. Steps 6 to 10 promote the change, as described in [promote changes between environments](./promote-between-environments.mdx#with-read-only-repositories).

### Prerequisites

- An instance with the repository connected as a read-only repository. Its `ref` on `main` is the Git branch that the instance tracks, `develop` in this example. [Connect a repository](./connect-repository.mdx) describes how.
- A local checkout of the repository with permission to open a merge request.

### Step 1: Create the change in a Git branch

Create the feature branch and the schema file as in [step 1 of the read-write workflow](#step-1-create-the-change-in-a-git-branch), and push it.

### Step 2: Import the Git branch onto an Infrahub branch

1. On the instance, create an Infrahub branch, for example `add-tag-color`.
2. On that Infrahub branch, set the `ref` of the repository to `feature/add-tag-color`. Changing the `ref` starts the import.

   ```graphql
   # against the Infrahub branch: https://<host>/graphql/add-tag-color
   mutation {
     CoreReadOnlyRepositoryUpdate(data: {
       id: "<repository-id>"
       ref: { value: "feature/add-tag-color" }
     }) { ok }
   }
   ```

3. Test the change on `add-tag-color`. To change the schema, push another commit to `feature/add-tag-color` and run **Import latest commit** on the Infrahub branch.

:::tip Load the schema with infrahubctl while you iterate

To skip the commit and the import while you develop, load the schema file onto the Infrahub branch with [`infrahubctl`]($(base_url)infrahubctl/infrahubctl):

```shell
infrahubctl schema load schemas/tags.yml --branch add-tag-color
```

Commit the final version to Git, because only the Git import makes the change promotable to other instances.

:::

### Step 3: Merge the Git branch

On your Git host, merge the merge request from `feature/add-tag-color` into `develop`.

### Step 4: Point the `ref` back to the tracked branch

On `add-tag-color`, set the `ref` back to `develop`, which now holds the change. Changing the `ref` starts the import.

When you merge an Infrahub branch, Infrahub also applies its `ref` to `main`. If you skip this step, `main` tracks `feature/add-tag-color` from then on.

### Step 5: Merge the change into `main`

Open a Proposed Change from `add-tag-color` to `main`, review it, and merge it. The instance's `main` now has the `color` attribute, and its `ref` is still `develop`.

Objects that you created on the Infrahub branch while you tested, such as a test Tag, also merge into `main`. If you created test objects, use a new Infrahub branch for steps 4 and 5 instead.
