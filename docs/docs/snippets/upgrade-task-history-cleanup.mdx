When the task manager reports at least 100,000 finished task runs older than the task history retention, the last step of the upgrade, `Step 7/7: Task history cleanup`, deletes them and gets their disk space back. On an existing instance that holds a lot of task history, run the cleanup command below once the instance runs again when that step skipped the cleanup and printed the command, or printed `The upgrade goes on without the cleanup`. You do not need to stop anything. New and small instances do not need it, with one exception: an instance with fewer than 100,000 old runs whose activity log tables are mostly free space, for example after the task manager deleted a burst of the events it stores for its own use. The upgrade skips the cleanup on such an instance, and the command returns that space to the disk. See [Clean up old task history during and after the upgrade](../deploy-manage/maintain-upgrade/upgrade/overview.mdx#clean-up-old-task-history-after-the-upgrade).
